Overview

总览

Platform Thinking

Eastlink 是什么：客户给一个 Brief，平台把它变成一组"选对了的供应商"和"确认过的设计"

客户提交 Brief → 拆解成需求包 → 先设计并定稿 → 按维度匹配打样候选 → 候选打样比样 → 客户确认定商 → 合作。所有需要人做判断的动作统一进右侧审核中心；所有资源沉淀在客户、供应商、项目三份主数据里。

需求包状态机设计中 → 待选打样候选 → 打样名单内审 → 打样中 → 定商建议内审 → 待客户定商 → 已确认合作；设计定稿自动进入匹配，客户可换选 / 加打样（记录原因）。
为什么先设计后打样设计定稿是打样前提——候选按同一套定稿出样，比样才公平；客户确认的是"设计稿"和"比样后的定商建议"两个节点。
打样比样候选各自出样，按质量 / 工艺还原 / 报价三项评分；全部评分后按综合分生成定商建议，依据全程留痕。

Matching Model

匹配模型：硬性门槛 + 加权排序两层

硬性门槛档位说明
准入状态固定硬性必须"已准入 / 合作中"，否则不进入候选
品类覆盖固定硬性主营或兼营须覆盖需求品类
工艺全覆盖固定硬性缺任一需求工艺即排除——做不了就是做不了，不存在"工艺 60 分"
认证全齐可切换（默认评分）打样期间可补办认证；对严格需求可一键切为硬性排除
客户验厂红线可切换（默认警示）打样可并行补审、下单前须完成；可切为硬性排除。正式版按需求包字段级配置
加权排序维度（8 维）默认权重数据来源计算口径
品类专精20主营 / 兼营品类主营 100，兼营 82
认证覆盖17资质证书需求认证覆盖率，缺项列入风险提示
质量表现15质量通过率直接取值
交付可靠12准时率 + 平均交期准时率 60% + 交期达标 40%
价格竞争力12报价竞争力指数直接取值
产能匹配9月产能 vs 需求量富余 1.5 倍满分，不足按比例扣
客户经验8服务过的客户服务过该客户 100 / 有出口经验 65 / 无 40
风险等级7风险评级低 100 / 中 60 / 高 25
为什么分两层工艺这类是"能不能做"的问题，属于门槛；质量价格交期是"谁做得更好"的问题，属于排序。混在一起打分会把"做不了"的供应商排进名单。
门槛开关认证与验厂红线支持现场切换硬性/评分档位，候选实时掉入漏斗排除名单——访谈时直接演示两种口径的差别。
输出漏斗全程透明（每一步排除了谁、为什么）+ 总分 + 维度得分条 + 推荐理由与风险提示；最终由人勾选，系统记录依据。

Roles

角色权限矩阵

业务员管理层客户供应商
总览全量 + 待办全量 + 风险仅自己项目与待确认仅自己的合作
项目管理可操作只读仅自己项目，只读不可见
匹配工作台核心操作不开放不可见不可见
供应商管理全池全池只读"我提供的"全量 + "合作中的"，无内部评分仅自己档案
客户管理可操作只读不可见不可见
审核中心内审动作查看设计定稿 / 定商确认（可换选）打样任务 / 合作通知

原则：客户看不到供应商池全貌、内部打分与落选者；供应商看不到竞争对手。内部角色是否再拆"业务员 / 采购"两条线，见下方确认清单第 ⑤ 条。

To Confirm With Sales

待业务员确认清单（拿着本 Demo 对照访谈）

① Brief 承接与拆解实际 Brief 长什么样（正式文件还是微信几句话）？拆解谁在做、按什么习惯拆？有没有一个需求包拆给两家分单的情况？
② 匹配维度校准选供应商最看重的前三个因素？有没有一票否决项（指定认证、必须验厂）？客户提供的供应商是"必须优先"还是"仅供参考"？维度数据现在记在哪？
③ 内审与客户确认内审谁来审——业务员还是主管？客户实际怎么确认供应商（邮件/会议/全权委托）？换选一般给什么理由？
④ 设计与打样顺序 ✅ 已确认已确认：先设计定稿 → 候选供应商打样 → 比样后定商（本 Demo 已按此实现）。待补充确认：打样候选名单是否需要客户确认（Demo 假设只内审）？打样费用谁承担？
⑤ 内部角色分工谁接 Brief、谁拆解、谁选供应商、谁对客户？要不要拆成业务员 / 采购两条线？一个业务员同时跟几个项目？
⑥ 现状痛点整个流程最耗时、最容易出错的是哪一步？现在靠什么在管（Excel/微信/邮件）？最想被系统替代的是哪部分？

Roadmap

分期规划

P1 · 本 Demo 范围三份主数据 + Brief 拆解 + 需求包匹配（多维度打分）+ 内审/客户确认流 + 设计稿协同 + 角色权限。
P2 · 系统化协同真实后端与账号体系、客户在线门户、供应商门户（接任务/报价）、打样与订单跟进、绩效数据沉淀。
P3 · 智能化匹配模型基于历史成交自学习、AI 拆解 Brief、AI 推荐供应商与风险预警。
