# Eastlink 合作供应商平台 · Demo V0.2

一个纯前端交互原型（Mock 数据，无后端），用于对内讲解和与业务员确认流程。核心回答三个问题：

1. **客户给我们一个 Brief 之后，平台上发生什么？**（业务主线状态机）
2. **供应商是怎么"算"出来的？**（多维度匹配打分）
3. **不同的人登录后各看到什么？**（角色切换模拟登录）

## 运行方式

无需安装任何东西，直接用浏览器打开 `index.html` 即可；或在目录下起一个静态服务：

```bash
python3 -m http.server 8080
# 浏览器访问 http://localhost:8080
```

## 一、业务主线（先设计 → 打样 → 定商；流转最小单位是"需求包"）

一个 Brief 拆成 N 个需求包；**需求包内继续拆到 SKU 维度**（编号 / 规格材质 / 数量 / 目标单价 / 状态，项目详情点「N 个 ▾」展开，新建 Brief 时自动生成 SKU 占位）。每个需求包先设计定稿，再选候选打样，比样后指定合作供应商。项目状态由需求包汇总得出。

```
项目：Brief接收 → 拆解中 → 设计中 → 匹配与打样 → 定商确认 → 已确认合作（P2：大货）

需求包：设计中 → 待选打样候选 → 打样名单内审 → 打样中 → 定商建议内审 → 待客户定商 → 已确认合作
            ↑（设计定稿自动进入匹配）        ↑                              │
            └────────────────── 客户要求换选 / 加打样（记录原因）───────────┘

设计稿（挂在需求包下、带版本，先于打样）：
V1 上传 → 内审 → 客户确认 → 定稿 ✓（定稿后需求包才进入打样候选匹配）
                   └→ 修改意见（记录原文）→ 上传 V2 重新走

打样比样：候选各自按定稿设计出样 → 质量/工艺还原/报价三项评分 → 按综合分生成定商建议
```

客户有两个确认节点：**确认设计稿定稿**、**确认比样后的定商建议**（可要求换选/加打样）。打样候选名单只走内审（Demo 假设，待业务访谈验证）。

## 二、供应商匹配：硬性门槛 + 加权排序两层

**为什么分两层**：工艺这类是"能不能做"的问题——缺了需求工艺就做不了产品，打 60 分没有意义，属于**硬性门槛**；质量/价格/交期是"谁做得更好"的问题，属于**加权排序**。混在一起打分会把"做不了"的供应商排进名单。

**硬性门槛（不满足 → 直接进漏斗排除名单，注明原因）**：

| 门槛 | 档位 | 说明 |
|---|---|---|
| 准入状态 | 固定硬性 | 必须"已准入 / 合作中" |
| 品类覆盖 | 固定硬性 | 主营或兼营覆盖需求品类 |
| **工艺全覆盖** | **固定硬性** | 缺任一需求工艺即排除（如"缺工艺：模切"） |
| 认证全齐 | 可切换（默认评分） | 打样期间可补办认证；可一键切为硬性 |
| 客户验厂红线 | 可切换（默认红色警示） | 打样可并行补审、下单前须完成；可切为硬性。正式版按需求包字段级配置 |

**加权排序（8 维，权重可调、拖滑杆实时重排）**：

| 维度 | 默认权重 | 数据来源（供应商档案字段） | 计算口径 |
|---|---|---|---|
| 品类专精 | 20 | 主营 / 兼营品类 | 主营 100 分，兼营 82 分 |
| 认证覆盖 | 17 | 资质证书 | 需求认证覆盖率，缺项列入风险提示 |
| 质量表现 | 15 | 质量通过率 | 直接取值 |
| 交付可靠 | 12 | 交付准时率 + 平均交期 | 准时率 60% + 交期达标 40% |
| 价格竞争力 | 12 | 报价竞争力指数 | 直接取值 |
| 产能匹配 | 9 | 月产能 vs 需求量 | 富余 1.5 倍满分，不足按比例扣 |
| 客户经验 | 8 | 服务过的客户 | 服务过该客户 100 / 有出口经验 65 / 无 40 |
| 风险等级 | 7 | 风险评级 | 低 100 / 中 60 / 高 25 |

**输出**：六档漏斗全程透明（池 → 准入 → 品类 → 工艺达标 → 候选排序 → 已选，每步排除了谁、为什么）+ 总分 + 维度得分条 + 推荐理由 + 风险提示。

**供应商来源**：档案带「来源」字段——`客户提供`（标注哪个客户移交/指定）或 `自主开发`。客户提供的供应商可整组置顶；可见不等于可用，未完成准入的照样被硬过滤挡住，但原因透明展示。

## 三、角色与权限（Demo 顶部左侧可切换视角，模拟登录）

| | 业务员（项目Owner） | 管理层 | 客户（HEMA） | 供应商（供应商 E） |
|---|---|---|---|---|
| 总览 | 全量 + 待办 | 全量 + 风险 | 仅自己项目与待确认 | 仅自己的合作 |
| 项目管理 | 可操作 | 只读 | 仅自己项目，只读 | 不可见 |
| 匹配工作台 | 核心操作 | 不开放 | 不可见 | 不可见 |
| 供应商管理 | 全池 | 全池只读 | "我提供的"全量 + "合作中的"，无内部评分 | 仅自己档案 |
| 客户管理 | 可操作 | 只读 | 不可见 | 不可见 |
| 审核中心 | 内审动作 | 查看 | 批准 / 要求换选 / 设计稿定稿或修改意见 | 合作通知 |

关键原则：客户看不到供应商池全貌、内部打分与权重、落选者；供应商看不到竞争对手。客户提供的供应商是客户自己的资产，对该客户全量可见（含未准入的）——平台帮客户把他的供应商盘子管出质量，这是服务卖点。

**右栏随当前页面上下文切换**（业务员/管理层）：总览=全量审核；项目详情=只看当前项目（可切全部）；匹配台=只看匹配与定商事项；客户管理=客户情报（待确认/红线/动态）；供应商管理=供应商情报（打样任务/合作包/证书）；平台思路=演示动线遥控器。客户与供应商角色的右栏保持各自的待办/通知不变。

## 四、演示动线（拿着 Demo 讲给别人听）

> 这条动线已内置成「平台思路」页右栏的**演示动线遥控器**——每一步一个按钮，点击直达对应页面与状态。

0. （开场可选）平台思路页用全景导图讲 2 分钟全局：先设计 → 打样 → 定商的主线一目了然。
1. 「新建项目 · 接收 Brief」：选客户后自动带出该客户的 Brief 拆解模板与分品类价格带提示；现场拆包 → 需求包进入设计阶段。
2. 「HEMA 2027 开学季」项目：背包袋包演示设计闭环（V1 内审 → 客户提意见 → V2 → 客户定稿 → 自动进入打样候选匹配）。
3. 匹配工作台选「文具需求包」（设计已定稿）：漏斗 + 权重滑杆 + 客户验厂红线，勾 2 家打样候选 → 提交内审。
4. 审核中心内审通过 → 发出打样邀请，需求包进入打样。
5. 项目详情「打样与比样」：标记寄样 → 录入评分 → 全部评分后生成定商建议 → 内审 → 提交客户。
6. 切客户（HEMA）视角：看到定商确认卡（含各家样品评分对比）→ 确认合作（或填原因要求换选/加打样）。
7. 切供应商视角：打样任务卡（按定稿出样、寄样截止）+ 我的合作 SKU 明细表；看不到竞争候选与评分对比。
8. 客户管理页签演示品牌智能档案（定位/视觉禁区/价格带/决策链/Brief 模板）、**材料与色彩资产库**（Pantone 色卡 + 色差要求 + 认可/禁用材料，按品类自动带入匹配需求卡；对比 HEMA 禁 PVC 与 MINISO 软胶合规可用、HEMA 禁高饱和与 Flying Tiger 主打高饱和，讲清"客户差异化"）与合规验厂标准（红线直连匹配）；品牌资产、设计稿、Brief 原文、供应商证书、色卡、材料卡都能点开预览，「上传资产 / 上传新版本 / Brief 文件」走真实文件选择（图片原图预览，仅存本页内存）。

## 五、待业务员确认的清单 + 可编辑画板

Demo 内「平台思路」页内置了完整的确认清单（Brief 形态、拆解习惯、匹配权重校准、一票否决项、内审归属、客户确认方式、设计稿先后顺序、内部分工、现状痛点），拿着 Demo 对照访谈即可。

同页的**平台全景导图是一块可编辑画板**：访谈时当场把业务员的修正画上去——双击节点改文字、「+ 节点」加环节、选中节点后连线（四种线型带标签）、删除不存在的步骤。改动自动保存在本机浏览器（刷新不丢），「导出」生成 JSON 文件发回汇总，「导入」还原查看，「重置」两次点击还原默认画板。多人实时协同属于 P2 后端范围。

## 六、分期规划

- **P1（本 Demo 范围）**：客户/供应商/项目三主数据 + 品牌智能档案（结构化）与资产库 + 材料与色彩资产库（色卡/材料卡，按品类联动匹配） + 客户合规验厂标准（红线自动参与匹配校验）+ 供应商档案编辑管理 + 新建 Brief 向导（含品牌模板联动）+ 设计协同（先行定稿）+ 打样候选匹配 + 打样比样与定商建议 + 内审/客户确认流 + 供应商打样任务与 SKU 明细 + 角色权限 + 可编辑全景画板 + 文件预览与真实上传（设计稿/品牌资产/Brief/证书可点开，上传仅存内存）+ 需求包 SKU 维度明细 + 右栏上下文切换（含演示动线遥控器）。
- **P2**：真实后端与账号体系、客户在线门户、供应商门户（接任务/报价）、打样与订单跟进、绩效数据沉淀。
- **P3**：匹配打分模型自学习、AI 拆解 Brief、AI 推荐供应商与风险预警。
