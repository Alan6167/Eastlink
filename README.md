# Eastlink 合作供应商平台 · Demo V0.1

一个纯前端交互原型（Mock 数据，无后端），用于对内讲解和与业务员确认流程。核心回答三个问题：

1. **客户给我们一个 Brief 之后，平台上发生什么？**（业务主线状态机）
2. **供应商是怎么"算"出来的？**（多维度匹配打分）
3. **不同的人登录后各看到什么？**（角色切换模拟登录）

## 运行方式

无需安装任何东西，直接用浏览器打开 `index.html` 即可；或在目录下起一个静态服务：

```bash
python3 -m http.server 8080
# 浏览器访问 http://localhost:8080
```

## 一、业务主线（流转的最小单位是"需求包"）

一个 Brief 拆成 N 个需求包，每个需求包独立走完匹配和审核；项目状态由需求包汇总得出。

```
项目：Brief接收 → 拆解中 → 匹配中 → 待客户确认 → 供应商已确认 → 设计协同 → 设计定稿

需求包：待匹配 ──→ 内审中 ──→ 待客户确认 ──→ 已确认
           ↑          │             │
           └── 内审退回 ┘             │
           └──────── 客户要求换选（记录原因）

设计稿（挂在需求包下、带版本）：
V1 上传 → 内审中 → 待客户确认 → 客户定稿 ✓
                        └→ 修改意见（记录原文）→ 上传 V2 重新走
```

## 二、供应商匹配：先硬过滤，再多维度加权打分

**硬性过滤（直接排除，不打分）**：准入状态必须是"已准入 / 合作中"；品类必须覆盖需求包品类。被排除的供应商在漏斗里透明可见（谁、为什么）。

**打分维度（权重可调，Demo 里拖滑杆实时重排）**：

| 维度 | 默认权重 | 数据来源（供应商档案字段） | 计算口径 |
|---|---|---|---|
| 品类专精 | 20 | 主营 / 兼营品类 | 主营 100 分，兼营 82 分 |
| 工艺覆盖 | 15 | 工艺能力标签 | 需求工艺覆盖率 × 100 |
| 认证覆盖 | 15 | 资质证书 | 需求认证覆盖率，缺项列入风险提示 |
| 质量表现 | 12 | 质量通过率 | 直接取值 |
| 交付可靠 | 10 | 交付准时率 + 平均交期 | 准时率 60% + 交期达标 40% |
| 价格竞争力 | 10 | 报价竞争力指数 | 直接取值 |
| 产能匹配 | 8 | 月产能 vs 需求量 | 富余 1.5 倍满分，不足按比例扣 |
| 客户经验 | 5 | 服务过的客户 | 服务过该客户 100 / 有出口经验 65 / 无 40 |
| 风险等级 | 5 | 风险评级 | 低 100 / 中 60 / 高 25 |

**输出**：总分 + 各维度得分条 + 自动生成的推荐理由 + 风险提示（缺认证 / 产能缺口 / 交期超限）。

**供应商来源**：档案带「来源」字段——`客户提供`（标注哪个客户移交/指定）或 `自主开发`。客户提供的供应商可整组置顶；可见不等于可用，未完成准入的照样被硬过滤挡住，但原因透明展示。

## 三、角色与权限（Demo 顶部左侧可切换视角，模拟登录）

| | 业务员（项目Owner） | 管理层 | 客户（HEMA） | 供应商（供应商 E） |
|---|---|---|---|---|
| 总览 | 全量 + 待办 | 全量 + 风险 | 仅自己项目与待确认 | 仅自己的合作 |
| 项目管理 | 可操作 | 只读 | 仅自己项目，只读 | 不可见 |
| 匹配工作台 | 核心操作 | 不开放 | 不可见 | 不可见 |
| 供应商管理 | 全池 | 全池只读 | "我提供的"全量 + "合作中的"，无内部评分 | 仅自己档案 |
| 客户管理 | 可操作 | 只读 | 不可见 | 不可见 |
| 审核中心 | 内审动作 | 查看 | 批准 / 要求换选 / 设计稿定稿或修改意见 | 合作通知 |

关键原则：客户看不到供应商池全貌、内部打分与权重、落选者；供应商看不到竞争对手。客户提供的供应商是客户自己的资产，对该客户全量可见（含未准入的）——平台帮客户把他的供应商盘子管出质量，这是服务卖点。

## 四、演示动线（拿着 Demo 讲给别人听的 9 步）

1. 业务员视角看总览：项目阶段分布、待办、动态。
2. 进入「HEMA 2027 开学季」：Brief 结构化字段 + 拆出的 3 个需求包（文具/包袋/水杯）。
3. 匹配工作台选「文具需求包」：看漏斗（12 家 → 状态过滤 → 品类过滤 → 候选），拖权重滑杆看排序变化。
4. 勾选 2 家进推荐名单 → 提交内审。
5. 右侧审核中心：内审通过 → 提交客户。
6. 切到客户（HEMA）视角：界面变了，只看到待确认名单 → 批准（或填原因要求换选）。
7. 切回业务员：需求包已确认，项目阶段推进。
8. 客户视角打开「供应商」：看到"我提供的供应商"全量（含一家准入未完成的，状态透明）。
9. 「HEMA 2026 秋冬家居」设计稿闭环：V1 有客户修改意见 → 业务员提交 V2 → 内审 → 客户定稿。

## 五、待业务员确认的清单

Demo 内「平台思路」页内置了完整的确认清单（Brief 形态、拆解习惯、匹配权重校准、一票否决项、内审归属、客户确认方式、设计稿先后顺序、内部分工、现状痛点），拿着 Demo 对照访谈即可。

## 六、分期规划

- **P1（本 Demo 范围）**：客户/供应商/项目三主数据 + Brief 拆解 + 需求包匹配 + 内审/客户确认流 + 设计稿协同 + 角色权限。
- **P2**：真实后端与账号体系、客户在线门户、供应商门户（接任务/报价）、打样与订单跟进、绩效数据沉淀。
- **P3**：匹配打分模型自学习、AI 拆解 Brief、AI 推荐供应商与风险预警。
